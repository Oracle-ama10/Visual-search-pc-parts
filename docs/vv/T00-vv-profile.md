## 2. ระบบของเรา
 
**ระบบนี้ทำอะไร**
 
เว็บแอปพลิเคชันที่ให้ผู้ใช้ถ่ายหรืออัปโหลดรูปอะไหล่คอมพิวเตอร์มือสอง ครอบตัดเฉพาะชิ้นที่สนใจ แล้วระบบแปลงภาพเป็นเวกเตอร์ด้วยโมเดลสกัดคุณลักษณะภาพ (ตั้งต้น CLIP ViT-B/32) และค้นหารุ่นที่คล้ายที่สุดใน PostgreSQL + pgvector พร้อมแสดงสเปกและราคา ถ้าคะแนนความคล้ายอันดับ 1 ต่ำกว่าเกณฑ์ ระบบจะไม่แสดงผล (Hard Block) และแจ้งว่าไม่พบรายการที่ตรงกัน ผู้ดูแลระบบจัดการคลังอะไหล่ ตั้งเกณฑ์ความคล้าย และดูประวัติการค้นหาผ่านหน้าหลังบ้าน
 
**ผู้ใช้หลักและผู้มีส่วนได้ส่วนเสีย**
 
| กลุ่ม | ใช้ระบบทำอะไร / ได้รับผลกระทบอย่างไร |
|---|---|
| ผู้ซื้อ และช่างซ่อม/ประกอบคอมพิวเตอร์ (ผู้ใช้หลัก) | ค้นหารุ่นอะไหล่มือสองที่ไม่มีหรืออ่านสติกเกอร์ชื่อรุ่นไม่ได้ ถ้าระบบผิด อาจได้รุ่นผิดและซื้ออะไหล่ไม่ตรงกับเครื่อง |
| ผู้ขายอะไหล่มือสอง | อ้างอิงสเปกและราคากลางก่อนลงขาย |
| ผู้ดูแลระบบ | ดูแลคลังข้อมูลอะไหล่และเกณฑ์ความคล้าย |
 
**ผู้ใช้จริงที่จะชวนมาทำ UAT ได้:** ร้านค้าคอมพิวเตอร์ของคนรู้จัก · นักศึกษาที่สนใจ
 
**การ deploy**
 
| สภาพแวดล้อม | ตอนนี้ |
|---|---|
| ทดสอบ | API รันบนเครื่องผู้พัฒนา (ประมวลผลโมเดลบน CPU) ต่อฐานข้อมูล PostgreSQL + pgvector บนบริการ Neon (ภูมิภาค Singapore) |
| ใช้งานจริง | ยังไม่ได้ deploy ต้องเลือกที่ deploy ก่อนช่วง UAT |

## 5. ส่วนที่ทีมคิดว่าเสี่ยงที่สุด 3 อย่าง
 
ใช้ในการวางแผนการทดสอบตามความเสี่ยงครั้งที่ 5 (CP2)
 
| ส่วนของระบบ | ทำไมคิดว่าเสี่ยง | ถ้าพังจะกระทบใคร อย่างไร |
|---|---|---|
| **1. ความแม่นยำของการค้นหาด้วยภาพ** (โมเดลสกัดคุณลักษณะ + ชุดข้อมูล) | ชุดทดสอบมีแค่ 11 ภาพ (ในคลัง 9) และคลัง 32 ภาพ ความต่างหนึ่งภาพเท่ากับ 11 จุดเปอร์เซ็นต์ · Top-5 ล่าสุด 81.82% ยังต่ำกว่าเป้า 85% (NFR-02) · พบว่าโค้ดเคยโหลดโมเดลด้วยการตั้งค่าที่แม่นยำน้อยกว่า | ผู้ซื้อและช่างได้รุ่นอะไหล่ผิด อาจซื้ออะไหล่ที่ใส่กับเครื่องไม่ได้ ผู้ขายตั้งราคาผิด และระบบไม่ผ่านเกณฑ์ความแม่นยำ |
| **2. เกณฑ์ความคล้ายและกลไก Hard Block** | ค่าเกณฑ์ 0.89 ตั้งจากข้อมูลน้อยมาก · ค่าเดิม 0.9241 ตัดผลที่ถูกทิ้ง · คะแนนโคไซน์เปลี่ยนช่วงเมื่อเปลี่ยนโมเดล · ภาพนอกคลังที่ใช้ทดสอบมีแค่ 2 ภาพ | เกณฑ์สูงไป: ผู้ใช้ไม่ได้ผลลัพธ์ทั้งที่อะไหล่มีในคลัง · เกณฑ์ต่ำไป: ระบบแสดงอะไหล่ที่ไม่เกี่ยวข้องเหมือนเป็นคำตอบ |
| **3. ความปลอดภัยของ API หลังบ้านและการอัปโหลดไฟล์** | `JWT_SECRET` ยังใช้ค่าเริ่มต้นสำหรับพัฒนา · CORS เปิดทุกโดเมน · รับไฟล์ภาพจากผู้ใช้โดยตรง · endpoint ผู้ดูแลแก้ข้อมูลคลังและเกณฑ์ได้ | ผู้ไม่มีสิทธิ์อาจปลอมโทเคนเข้าแก้คลังอะไหล่หรือเกณฑ์ ทำให้ผลค้นหาของผู้ใช้ทุกคนผิด หรืออัปโหลดไฟล์อันตรายขึ้นเซิร์ฟเวอร์ |
